SQS bills API requests (each Send/Receive/Delete/ChangeVisibility call, per 64 KB chunk; every SeatRelay message is far below 64 KB), not messages. Per queue:

```
requests = sends + EmptyReceives + receive_calls + delete_calls
  sends         = Sent                  (one SendMessage per message: api intake, forwarder, sweep;
                                         SendMessageBatch of <= 10 timers per commit on *-expiry-delay -> low = ceil(Sent/10))
  EmptyReceives = NumberOfEmptyReceives (exact: each is one ReceiveMessage call that returned nothing)
  receive_calls = consumer Lambda invocations (one ReceiveMessage per batch), bounded to [ceil(Received/10), Received]
  delete_calls  = consumer Lambda invocations (one DeleteMessageBatch per batch), bounded to [ceil(Deleted/10), Deleted]
  (queues without a consumer: receive_calls = Received, delete_calls = Deleted)
```

Totals (low / **central** / high): FIFO 122,660 / **257,581** / 257,581 -> sqs_request_fifo; standard 50,210 / **118,443** / 118,661 -> sqs_request_standard. The JSON uses the central values.

Uncertainty: (1) one ReceiveMessage per Lambda batch is the event-source-mapping behaviour assumed for the central value; the pollers may fetch up to 10 messages per call and split them into BatchSize-1 invocations (fewer calls) or issue extra calls (more), hence the bounds; (2) NumberOfMessagesSent already includes deduplicated FIFO sends: on the drained commands queue Sent - Deduplicated equals Deleted, so the Deduplicated column is shown but not added; (3) calls that CloudWatch does not count are missing: GetQueueAttributes/PurgeQueue from the experiment scripts and the console, and the poller's ChangeMessageVisibility calls, if any. Messages moved to a DLQ by a redrive policy are not counted in Sent.
SendMessageBatch found in services/aws/src/adapters/sqs.ts (SqsTimerScheduler, delay queue only); SendMessage is used for commands.fifo (SqsCommandQueue, sweep, forwarder) and for re-delays.

## Not included

- Fixed monthly items: CloudWatch alarms (18 in these stacks), dashboards (2) and custom metrics (SeatRelay namespace, EMF) are billed per month, not per day; they are already fixed costs in model.py (cw_alarm_month, cw_dashboard_month, cw_custom_metric_month) and are left out of the day's usage.
- Storage (ddb_storage_gb_month, ddb_pitr_gb_month, s3_storage_gb_month, cw_logs_storage_gb_month) is metered in GB-month over time, not by the day's activity; table sizes now (describe-table, updated about every 6 h): seatrelay-dev 25.25 MB / 51,512 items, seatrelay-pilot 0.2442 MB / 479 items. One day's share is far below US$0.01.
- X-Ray traces (xray_trace_recorded/retrieved), S3 requests (CloudFront misses and deployments; S3 request metrics are not enabled), CloudWatch API requests (dashboards, experiment scripts and this script's GetMetricData), SNS alarm notifications and Budgets are not available as AWS/* metrics without extra configuration and are left out (all are inside their free allowances at this volume except GetMetricData, about US$0.001 per run of this script).
- registrations: no metric counts REGISTER commands; the key is omitted, so model.py prints no unit cost.

## Assumptions and uncertainty

- Resources are those listed by list-stack-resources for the stacks above now; metrics are summed by resource name, so a resource that existed earlier in the window under the same name is included.
- MemorySize and Architectures are read now and assumed constant over the window (a configuration change during the day would mis-weight GB-s).
- All Lambda functions are arm64, so lambda_request_arm and lambda_gbs_arm are used; an x86_64 function would be reported in the notes.
- GB = 2^30 bytes for logs, CloudFront and API data, consistent with model.py.
- HTTP API Count is taken as billable although authorizer rejections and throttled requests (part of 4xx) are not billed.
- SQS requests follow the formula in the SQS section; the JSON uses the central estimate, the low/high bounds are shown there.
- CloudFront requests and bytes are all priced at the Asia Pacific HTTPS / data-transfer rate (upper bound).
- SES Send is account level; the account runs no other SES workload.
- Cognito MAU = users in the pool (month-level upper bound), included as asked although it is not a per-day quantity.
- model.py applies monthly free-tier allowances to the window's quantities, so the after-free-tier total is the cost of this window if it were the only usage in its month.
