\section{Evaluation}\label{sec:evaluation}

\subsection{Method}
Commands went through the \code{dev} stage's public API as the browser sends them (client
\code{commandId}, POST, 202, polling as in \S\ref{sec:timers}). Crashes were injected with
\code{\_fault} flags that only \code{dev} honours, stale TICKs were sent directly to the FIFO queue,
and the notifier outage was simulated by setting its reserved concurrency to 0; \code{dev} records
notifications as SKIPPED without sending e-mail. Each script asserts its checks, calls \code{verify}
after its scenario steps and writes \code{results/<date>-<experiment>/}; each invocation repeats its
scenarios 3 times, and the invocation pinned in \code{report/series.json} is quoted. Expiry
experiments use $\text{holdSeconds} = 60$. The smoke test passed first
(\SmokeChecksPassed/\SmokeChecksTotal{} checks, run \code{\SmokeRunId}). The \SeriesExperiments{}
quoted invocations ran from a clean checkout of commit \code{\SeriesCommits}; all \SeriesDirtyRuns{}
are flagged dirty only because the runner appended to its own status log under \code{results/}.
After the series we downloaded the five deployed Lambda bundles: they are byte-identical to a build
of that commit, and no stack changed during the series
(\code{results/2026-10-17-table3-dev-q1000-provenance.md}). After the last redeploy (commit
\code{\RegressionCommit}: web interface, participant read views and notification wording; engine
decision code unchanged) we re-ran \RegressionExperiments: \RegressionChecksPassed/\RegressionChecksTotal{}
checks passed. Run ids and commits of every number are listed in \code{report/generated/numbers.tex}.

\paragraph{The first series failed, and why.}
The first series on \code{dev} ran under the new account's Lambda quota of
\ThrottleConcurrencyAccountConcurrencyMax{} concurrent executions, shared by all functions of both
stages. Its concurrency run passed \ThrottleFirstConcurrencyChecksPassed/\ThrottleFirstConcurrencyChecksTotal{}
checks, with HTTP 503 responses that carried no application error code; the backfill run failed
when one of its ten parallel workshop creations got the same 503 (the other nine lost REGISTERs
to it, yet relayed every expiry and passed \code{verify}); and the k6 matrix lost requests
from 25 VUs on. CloudWatch shows the cause (\code{results/2026-10-17-throttling-evidence/}): in all
\ThrottleWindows{} windows the API function's throttles, the API's 5xx count and the 503s in its access log are equal
(\ThrottleConcurrencyApiThrottles, \ThrottleBackfillApiThrottles{} and \ThrottleKsixApiThrottles{} of
\ThrottleKsixRequests{} requests), and account-wide concurrency peaked at exactly
\ThrottleKsixAccountConcurrencyMax. API Gateway answers 503 when it cannot invoke a throttled Lambda
integration. Even then \code{verify} found no invariant violation after any phase of that
concurrency run: throttling lost requests, not correctness. AWS then raised the quota to 1{,}000,
and we re-ran the whole series, smoke test first, on the same deployed code (only the sweep schedule
was renamed in between). Table~\ref{tab:results} quotes these re-runs: \SeriesPassed{} of
\SeriesExperiments{} experiments passed every check, and the failed runs remain in \code{results/}. The
first series' \emph{expiry-race} run also failed one check, unrelated to the quota: a probe meant to
arrive 200\,ms before \code{expiresAt} arrived after it (client send-timing jitter) and was rejected
as expired, as the server clock requires; the harness was changed to calibrate the send time
before the quoted re-run (\code{\ExpiryRaceRunId}). In all \ExpiryRaceOrderTimerFirst{} late
trials the timer had expired the offer before the ACCEPT arrived, so the opposite order did not occur
on \code{dev} (the engine's unit tests cover it). No stale tick changed a newer offer.

\subsection{Mechanism comparison: one queue vs per-session forms}\label{sec:mechanism}
The replay tool runs the production engine with a simulated clock and ideal timers on
\ReplaySeeds{} random workshops (\ReplayRangeSessionsMin--\ReplayRangeSessionsMax{} sessions,
\ReplayRangeOversubscriptionMin--\ReplayRangeOversubscriptionMax{} times oversubscribed, holds of
\ReplayRangeHoldSecondsMin--\ReplayRangeHoldSecondsMax\,s, random accept, decline, ignore, cancel and
hoarding behaviour). Each seed's identical arrival stream is replayed twice: in UNIFIED mode (SeatRelay) and in
PER\_SESSION mode, where a participant registers separately for every acceptable session, each
session has its own queue, and duplicates are released by hand only with some probability. One queue had
no duplicate holds, as C2 requires; per-session queues had
\ReplayDupHoldEventsPerSessionMean{} duplicate-hold events per workshop
[\ReplayDupHoldEventsPerSessionLo, \ReplayDupHoldEventsPerSessionHi] (Fig.~\ref{fig:replay}). One
queue served \ReplayDistinctUnifiedMean{} distinct participants per workshop against
\ReplayDistinctPerSessionMean{} (paired difference \ReplayDistinctDeltaMean{}
[\ReplayDistinctDeltaLo, \ReplayDistinctDeltaHi]; fewer under PER\_SESSION in
\ReplayDistinctFewerSeedsPct\,\% of seeds, equal in \ReplayDistinctEqualSeedsPct\,\%), and a released
seat reached a new participant after \ReplayRefillMeanUnifiedMean{} instead of
\ReplayRefillMeanPerSessionMean{} minutes on average (\ReplayRefillMeanN{} seeds with refills in both). Seats left empty
at cut-off did not differ (difference \ReplaySeatsWastedDeltaMean{}
[\ReplaySeatsWastedDeltaLo, \ReplaySeatsWastedDeltaHi]). This compares two modes of our own engine
under an assumed behaviour model: it is neither a field measurement nor a test of the tools in
Table~\ref{tab:competitors}; the plan's extra replay on the deployed system was not run.

\subsection{Real pilot, and a staged rehearsal reported separately}\label{sec:pilot}
The \code{pilot} stage (fault injection disabled, e-mail enabled; in the SES sandbox only
verified addresses get mail, others see in-app notifications) is deployed to serve a real
workshop in two sessions with registration open for at least five days; the organiser's CSV exports
and the dashboard's backfill log will be the evidence. \pending{pilot workshop, dates and
observations: natural cancellations, backfills, notifications, attendance, organiser feedback}.
\emph{Staged, not user evidence:} before the pilot, a scripted rehearsal on the pilot stage with
\RehearsalParticipants{} synthetic accounts (\code{results/2026-10-17-pilot-rehearsal-3/}) applied
\RehearsalCommandsApplied/\RehearsalCommands{} commands, relayed \RehearsalBackfills{} seats
(\RehearsalBackfillExpiredN{} expiries through the timer path in
\RehearsalBackfillExpiredMinMs--\RehearsalBackfillExpiredMaxMs\,ms; declines, cancellations and a
capacity increase in their own transaction), sent \RehearsalNotificationsSent{} e-mails to the SES
mailbox simulator and passed \RehearsalChecksPassed/\RehearsalChecksTotal{} checks; the invariants
held at all \RehearsalInvariantReads{} checkpoints. As the Preliminary report requires, these
rehearsed events are logged apart from the pilot's natural events and, like the team organiser's
observations, are internal operational evidence; only independent participants' feedback is user
evidence.

\subsection{Hypotheses H1--H3: verdicts on the evidence so far}\label{sec:hypotheses}
\begin{itemize}
\item \textbf{H2} (the cross-session constraint removes the capacity waste of duplicate holds):
  \emph{supported in simulation, not yet in the field.} One queue had no duplicate holds against
  \ReplayDupHoldEventsPerSessionMean{} duplicate-hold events per workshop with per-session queues and
  served \ReplayDistinctUnifiedMean{} instead of \ReplayDistinctPerSessionMean{} distinct participants
  (\S\ref{sec:mechanism}); seats left empty at cut-off did not differ, so the waste removed is
  capacity tied up by duplicates, not seats empty at the end. No \code{verify} call on \code{dev}
  found a C2 violation.
\item \textbf{H3} (automatic backfill reduces the organiser's manual handling): \emph{partly
  supported.} Every release is relayed in the same decision with no organiser step
  (\IfPending{\BackfillExpiredPNinetyFiveS}{\TimerPathRelaysN{} timer-path relays on \code{dev} took at most
  \TimerPathRelayMaxMs\,ms}{on \code{dev} \BackfillExpiredN{} expiry-driven backfills took p95
  \BackfillExpiredPNinetyFiveS\,s against the 120\,s target}; a cancellation is
  relayed inside its own transaction, \SmokeCancelBackfillMs\,ms), and in simulation per-session forms left
  \ReplayDupConfirmedPerSessionMean{} duplicate confirmed seats per workshop to clean up, against
  \ReplayDupConfirmedUnifiedMean{} with one queue. Open: \IfPending{\BackfillExpiredPNinetyFiveS}{the
  backfill-latency target (run aborted, \S\ref{sec:results}) and }{}\IfPending{\StudyParticipants}{the
  organiser's manual steps in the user study (\S\ref{sec:study}).}{\pending{H3: compare the organiser's
  manual steps in the user study}}
\item \textbf{H1} (unified registration reduces participant effort): \IfPending{\StudyParticipants}{\emph{not
  tested yet}; it rests on the user study's paired task times, completion, errors and help
  requests (\S\ref{sec:study}).}{\pending{H1 verdict from the user-study results (\S\ref{sec:study})}}
\end{itemize}
